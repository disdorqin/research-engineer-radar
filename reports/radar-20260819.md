**核心问题**：多优先级 LLM Serving 调度中，优先级粒度（tier 数量）如何在 SLO 分化与系统开销之间取得最优平衡

**真正值得学**：4 个优先级 tier 是性价比拐点：再多 tier 带来的额外成本（prefill 阶段集中开销）远大于收益；系统设计应在多维 trade-off 中搜索，而非直觉上越多越好

### 4. Demystifying Agent Skills: Why They Work-Until They Don't

- 分类：Agent Engineering

**核心问题**：Agent Skills 在实际生产中何时有效、为何有效、何时失效——以及如何归因和测量这些行为

**真正值得学**：Skill 的核心机制是 'procedural anchoring'（稳定轨迹而非注入事实），而 retrieval 是独立瓶颈：pool 从 5 增至 100 时 precision 从 29.6% 降至 3.3%。

**以后什么时候想起它**：设计 skill 系统、retrieval-augmented agent、或需要归因 skill 效果时；尤其当面临 skill pool 扩展与检索精度下降的 trade-off。

**关键 Trade-off**：Skills 提升聚合成功率但依赖 retriever 精度；confusable distractors 不影响 downstream success 但损害 offline identification。

**成熟系统信号**：8,135 trial records, controlled experiments across multiple benchmarks/harnesses/LLMs, paired trajectory analysis with 238 unique labels from 240 open-coded records.

**Agent 启发**：从 Demo 到可靠系统的差距在于：skill 不是知识注入而是执行锚定；要评估 skill 必须测量 retrieval precision 而非只看 task success。

**当前工作可选关联**：可直接迁移到 electricity price forecasting agent 的 skill design：retrieval bottleneck 在 skill pool 扩展时必然出现，需优先测量 retrieval precision。

**最小实验**：构建一个小型 skill pool（5/20/50/100 个 skill），测量 retrieval precision 与 task success 的关系，验证论文中 29.6%→3.3% 的下降曲线。

### 5. KV-Pipe: On the Relation Between KV Sharing and Pipeline Parallel Efficiency in LLMs

- 分类：性能工程
- 来源：arXiv
- 发布时间：2026-08-16T22:01:16+00:00
- 链接：https://arxiv.org/abs/2608.15943v1
- 最终分数：0.577
- 建议动作：浏览

**核心问题**：LLM pipeline parallelism 中的 stage imbalance 导致 GPU 利用率下降和迭代时间增加。

**真正值得学**：将 KV sharing 从仅用于推理成本优化拓展为 pipeline 负载均衡的系统级控制旋钮，通过离线阶段感知选择 attention 层做跨层 KV 复用，使 FLOPs Imbalance Ratio 趋近 1，实现训练吞吐与推理吞吐的双边收益。

**以后什么时候想起它**：遇到 LLM 分布式训练中 pipeline parallel 阶段负载不均、GPU 利用率瓶颈，或需要在同一机制上兼顾训练效率与长 context 推理成本时。

**关键 Trade-off**：跨层 KV sharing 减少了冗余投影计算但可能增加 memory access pattern 的复杂度；离线优化依赖准确的 per-layer FLOPs 估计，对新型架构泛化性有限；在 PP degree 越高时增益越显著但也意味着实现门槛更高。

**成熟系统信号**：报告了 9.2% MFU 提升和 9.8% 迭代时间减少，在多种 PP configuration 下验证；有量化 benchmark；但缺少 failure mode 分析、生产部署证据、和对不同模型架构的泛化测试。

**性能启发**：以 FIR (FLOPs Imbalance Ratio) 作为明确的度量指标定位瓶颈，用 tail-first 贪心策略迭代重定向 bottleneck stage，提供了一套可复现的测量-优化闭环思路。

### 6. FlashQuant: Sparse-Dense Fusion for Memory-Efficient Outlier-Aware LLM Inference

- 分类：性能工程
- 来源：arXiv
- 发布时间：2026-08-16T04:57:39+00:00
- 链接：https://arxiv.org/abs/2608.15531v1
- 最终分数：0.575
- 建议动作：浏览

**核心问题**：LLM 低比特量化解码时，outlier-aware 方法需要将 dense GEMM 和 sparse SpMM 两条路径分开执行，导致 activation/output tile 被重复写入全局显存，在 memory-bound 的自回归解码阶段造成显著冗余开销。

**真正值得学**：将本应分开的 dense 和 sparse 计算路径融合为单个 GPU kernel，通过 on-chip tile 共享避免 global memory 重复访问；这是 memory-bound 场景下的经典优化思路——减少访存比增加计算更有效。

**以后什么时候想起它**：处理 LLM 推理性能问题、低比特量化部署、GPU kernel fusion、memory-bound decoding 场景时，以及需要评估 outlier-aware 量化方案实际吞吐收益时。

**关键 Trade-off**：稀疏 outlier 的比例决定 SpMM 路径的代价；outlier 越多，tile 对齐和 bank conflict 控制越复杂，fused kernel 的设计收益越不确定。

**成熟系统信号**：有 benchmark（2.74x-4.18x vs cuBLAS BF16，1.53x vs unfused baseline），但仅报告解码阶段加速，缺少对 training、多 batch、不同模型尺寸、不同硬件上的泛化评测；arXiv preprint，尚无生产部署证据。

**性能启发**：定位瓶颈：outlier-aware 量化的 sparse path 和 dense path 分别调用独立 kernel，共享的 activation/output 产生双倍 global memory 读写。假设：fused kernel + on-chip tile 共享可消除冗余访存。验证：对比 cuBLAS BF16 和 unfused baseline 在 decoding 阶段的吞吐/延迟。
